## 2. 项目开发铁律（摘要，详见铁律文档）

1. **范围铁律**：本期只做局域网，禁止引入任何公网穿透/公网接入依赖。
2. **平台铁律**：主端/副端三平台同构，任一功能未覆盖三平台不得宣告完成。
3. **架构铁律**：严格三层（主端 / 中枢 / 副端）；Agent 不直接暴露地址给主端，远控媒体经中枢信令协商后 LAN 直连或中继；中枢为唯一控制平面。
4. **安全铁律**：全链路 TLS；关键指令（remote_control / uninstall / policy_apply）必须 HMAC-SHA256 签名 + `seq` 防重放；Agent 防卸载/防篡改/自校验；录像与日志加密存储。
5. **合规铁律**：屏幕/录像默认关闭，仅远程协助进行中或经审批安全事件开启；每次远控远端必弹提示；录像留存 ≤90 天自动清理；采集最小必要；上线前法务评审。
6. **交付铁律**：禁止"空口完成"——须带可验证证据（构建通过/真实运行/curl/JWT 等）；bug 修复后全量扫描同类问题；破坏性操作前明确风险确认。
7. **决策铁律**：白天（08:00–22:00）涉及方向/取舍/范围/样式/补后端的决策，先给建议+理由、用户拍板后再开工；夜间（23:00–07:00）自主决策推进，交付时逐条说明。
8. **进度铁律**：维护 `dev-status.md`，白天与夜间自动任务以之为唯一交接依据。
9. **协议铁律**：M1 冻结的协议/Schema/接口契约为基线，后续变更须 Gate 评审，禁止私自改契约导致三端不一致。
10. **质量铁律**：M4 远控为关键路径，须压测 ≥20 路并发；1000+ 规模须验证 ≥2000 终端心跳 + ≥50 路并发；CI 全绿方可进入下一里程碑。

## 3. 标准工作流

1. 读三文档 + 铁律 + `dev-status.md`，确定当前里程碑（M1–M6）与下一未完成任务。
2. 白天：凡决策类先给建议+理由交用户拍板；夜间：在铁律与已冻结契约范围内自主决策。
3. 实现顺序：先 M1 设计冻结产物（协议规范 / DB Schema / 跨平台接口契约 / 仓库脚手架），再 M2–M6。
4. 每次收尾更新 `dev-status.md`（里程碑 / 当前任务 / 状态 / 阻塞 / 时间）。
5. 交付须带可验证证据；无法自主决策项写入 `dev-status.md`「待用户决策」并汇报。

## 5. 夜间自主接管协议（供 23:00 自动任务调用）

入口流程：
1. 加载本 skill，严格遵循「项目开发铁律」。
2. 读 `dev-status.md` 与项目记忆日志，判断开发任务是否已停止/无进行中任务；若白天仍在活跃推进且无需接管，写简短记录后退出。
3. 若需接管，按排期 M1–M6 顺序从 `dev-status` 记录的下一未完成任务继续。
4. 夜间自主决策：在铁律与已冻结契约范围内自行决定实现细节/选型/取舍，不破铁律（尤其：只做局域网、三平台同构、安全与合规底线不可降级）。
5. 每完成一项更新 `dev-status.md`。
6. 工作至 07:00 或里程碑可交付节点即止；产《夜间开发报告》写入项目记忆当日夜间报告，含：完成项 / 进行中项 / 关键决策与理由 / 无法自主决策问题（仅列此类交白天拍板）/ 下一步建议。
7. 无法决策项（产品方向/范围/外部依赖/合规边界）写入报告「待用户决策」章节，不得臆测越权。
