# 御端（YuDuan）M6 高可用与合规上线设计

> 版本：v1.0 ｜ 关联：`终端统一管理平台-技术开发文档.md` M6、`御端-项目开发铁律.md`
> 范围：服务端中枢（Hub）高可用、数据层高可用、副端容错、审计与合规上线清单。
> 定位：本期仅限局域网；公网远控为 P2 远期目标，本文的 TLS/合规基线同样为远期公网化预留。

---

## 1. 高可用目标与单点分析

| 组件 | 单点风险 | 可用性目标（局域网内） | 策略 |
| --- | --- | --- | --- |
| Hub 中枢 | 进程崩溃 / 主机宕机 | 99.5%（月停机 < 3.6h） | 多实例 + 前置负载均衡 + Agent 自动重连 |
| PostgreSQL | 主机宕机 / 磁盘故障 | 99.9% | 主从流复制 + 自动故障转移（或受管 HA） |
| 副端 Agent | 网络闪断 / 主机休眠 | 尽力在线 | 断线重连 + 令牌复用 + 指数退避 |
| 控制台 | 无状态页面 | 随 Hub | 静态页由各 Hub 实例同源托管 |

**核心原则**：Hub 设计为**无状态**（长连接为有状态但可快速重建），所有持久状态收敛到 PostgreSQL。
Hub 重启不丢设备台账、账号、审计；副端通过令牌在重连后复用既有设备身份（`MemStore.Upsert`/`PostgresStore` 的 `byToken` 逻辑已验证）。

## 2. 服务端中枢（Hub）高可用

### 2.1 多实例 + 负载均衡
```
                 ┌─────────────────────────────┐
   副端 Agent ──▶ │  L4/L7 负载均衡（sticky by token / IP）│
                 └───────┬─────────────┬───────┘
                         ▼             ▼
                    ┌─────────┐   ┌─────────┐
                    │ Hub #1  │   │ Hub #2  │   …… 共享同一个 PostgreSQL
                    └────┬────┘   └────┬────┘
                         └──────┬──────┘
                                ▼
                       ┌─────────────────┐
                       │ PostgreSQL 主库  │
                       └─────────────────┘
```

- **长连接粘性**：Agent 的 `ws://.../ws/agent` 长连接需粘在某一 Hub 实例（按来源 IP 或注册令牌哈希做 sticky session）。负载均衡建议 Nginx（`ip_hash`）/ HAProxy（`balance source`）/ 云 SLB 会话保持。
- **无状态扩容**：Hub 不持有跨实例必需的内存态；设备在线态、待回执任务为实例内短时状态，实例重建即恢复。
- **健康检查**：`GET /api/v1/report`（需令牌）或新增 `GET /healthz`（免鉴权，仅探活）作为 LB 健康检查端点。

### 2.2 指令路由的跨实例问题（已知限制 & 演进）
- 当前 `handleDeviceCmd` 只能把指令发给**本实例**持有的该设备长连接。多实例下，若指令落到非设备所在实例，会返回 `device offline`。
- **局域网 MVP 缓解**：控制台 REST 与 Agent 长连接走**同一 Hub 实例**（同域 sticky），运维规模（数百–一千终端）单实例可承载，先以「主实例 + 热备」运行。
- **P2 演进**：引入实例间总线（Redis Pub/Sub 或 PG `LISTEN/NOTIFY`）做指令转发，或改为「指令经 PG 排队、设备所在实例消费」模型，彻底去粘性。见技术文档 M6 演进节。

### 2.3 滚动升级
- Hub 无状态 ⇒ 可蓝绿/滚动重启；LB 先摘流量 → 优雅关闭（`SIGTERM` 触发 `http.Server.Shutdown`，等待在途指令回执）→ 起新版本 → 恢复流量。
- 副端对 Hub 重启无感（自动重连），但**在途指令会超时**（当前 shell 15s / sw_install 120s），重连后需重发。

## 3. 数据层高可用（PostgreSQL）

- **主从流复制**：一主一从（同步或异步），从库可接管只读查询（报表）。故障时提升从库为主，Hub 通过 DSN/VIP 指向新主。
- **连接与池化**：当前零依赖 `internal/pg` 为单连接简单查询；生产替换为 `pgx`/`lib/pq` + 连接池（`max_open_conns`、空闲回收、健康探测），并加查询超时。
- **备份**：每日 `pg_dump` 逻辑备份 + WAL 归档；保留 ≥ 30 天。设备台账/账号/审计均可由备份重建。
- **Schema 迁移**：`PostgresStore.migrate()` 用 `CREATE TABLE IF NOT EXISTS` 幂等建表；生产引入版本化迁移（如 golang-migrate）管理增量 DDL。
- **参数化查询**：现有内联转义 `q()` 仅适配演示；生产必须参数化，杜绝 SQL 注入（铁律 4）。

## 4. 副端（Agent）容错

- **断线重连**：`run()` 返回错误后 5s 重连（Go 参考端）；生产建议指数退避（5s→10s→…→60s 上限）+ 抖动，避免惊群。
- **令牌复用**：首次注册获 `token`，重连时回传，`Upsert` 命中 `byToken` 复用设备身份，不产生重复台账（已实测：重启后台账不变）。
- **心跳**：30s 心跳；Hub reaper 90s 无心跳标记离线（`StartReaper`）。离线仅影响在线态，不影响台账。
- **本地缓存**：Rust 生产端可缓存上次资产与令牌到本地，弱网时先上线后补采。

## 5. 审计与合规上线清单

### 5.1 审计（铁律：管理操作全程留痕）
- 已落库事件：`login`（成功/失败）、`command`、`rc_start`、`software_upload`、`dir_sync`。
- 字段：actor / action / target / detail / result / time。存储于 PG `audit_events`，支持 `?limit=` 分页查询（`/api/v1/audit`，需 `audit:view`）。
- **合规增强（上线前）**：
  - 审计**只追加不修改**（生产加 DB 触发器禁 UPDATE/DELETE，或写入 WORM 存储）。
  - 留存周期 ≥ 180 天（等保/内控常见要求），超期转冷存。
  - 关键操作（改密、批量指令、远控开启）实时告警到值班群。

### 5.2 上线合规清单（Checklist）
| # | 项 | 现状 | 上线要求 |
| --- | --- | --- | --- |
| 1 | 传输加密 | 已支持 TLS（自签，:8443） | 强制 `https/wss`，关闭明文 :8080；换发内网 CA 证书 |
| 2 | 指令签名 | 已支持 HMAC-SHA256 + nonce | 生产 `YUDUAN_HMAC_ENFORCE=1`，副端强制验签 + 防重放 |
| 3 | 密钥管理 | 环境变量注入 | 密钥入 KMS/密钥柜，定期轮换；禁止硬编码/入库 |
| 4 | 默认口令 | admin/admin123 等演示口令 | 首次登录强制改密；或禁用内置口令改用目录认证 |
| 5 | 目录认证 | AD/LDAP 同步已实现 | 生产对接真实 AD（`//go:build ldap` + go-ldap），Kerberos/LDAP bind 取代演示口令 |
| 6 | 口令存储 | SHA256+pepper（演示） | 换 argon2id/bcrypt（铁律 4 安全里程碑） |
| 7 | RBAC | admin/operator/viewer | 按最小授权分配；禁用多余账号；定期复核 |
| 8 | 软件仓库下载 | `/api/v1/repo/` 演示放开 | 改短时效签名 URL 或鉴权，防未授权拉取 |
| 9 | SQL 注入 | 内联转义（演示） | 参数化查询 |
| 10 | 依赖与漏洞 | 当前 Go 零三方 / Rust 纯 std | 引入依赖后接 SCA 扫描 + CI |

### 5.3 合规边界（员工隐私）
- 远控画面/输入涉及员工终端，须保留**被控端合规提示与确认**（M4 `rc_event` 的 `consent_required`，已实现）；审计记录 operator、时间、设备。
- 资产采集字段白名单化，禁止采集与运维无关的个人数据。

## 6. 监控与告警

- **指标**：在线设备数、指令成功率/时延、Hub QPS/长连接数、PG 连接数/慢查询、审计写入速率。
- **日志**：Hub 结构化日志集中到内网日志平台；Agent 本地日志按级别采样上报。
- **告警**：Hub 实例全离线、PG 主从延迟超阈、指令失败率突增、登录失败突增（爆破嫌疑）。

---

## 7. 灾备与演练

- **RTO/RPO**：Hub 分钟级恢复（无状态重启）；数据 RPO ≤ 5 分钟（WAL 归档）。
- **演练**：每季度一次「杀 Hub 主实例」「PG 主从切换」演练，验证副端重连与台账不丢。
